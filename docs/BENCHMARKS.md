# Измерения: Lite.Union против других библиотек

> **Статус: заготовка.** Методика и сам стенд готовы и проверены (все адаптеры дают одинаковые результаты), но сами замеры ещё не сняты. Таблицы появятся в разделе «Результаты» после прогона; пока там пометки `TODO`. Цифр из этого файла нельзя цитировать, пока их нет.

Здесь сравниваются **все три раскладки Lite.Union** (`Overlap`, `Flat`, `Boxed`) с другими библиотеками union'ов для C#. Цель не «показать, что мы лучше», а честно увидеть, где выигрываем, где проигрываем и где разницы нет.

## Что сравнивается

## Наборы типов

Каждый набор состоит из восьми типов; union из 3 кейсов берёт первые три, union из 8 кейсов все восемь.

| Набор | Содержимое | Зачем |
|---|---|---|
| `Values` | `int`, `long`, `double`, `Guid`, `byte`, `short`, `float`, `DateTime` | только числа: максимум выгоды от перекрытия |
| `Refs` | `string`, четыре класса и `record class`, `int[]`, `List<int>` | только ссылки: типичный `Result`/`Error` |
| `Mixed` | структуры вроде `{ int; string }`, `{ string; long }`, `{ object; int }` | число и ссылка в одной структуре: сложный случай, сильная сторона Lite.Union |
| `Big` | по 64 байта на кейс (часть с полем `string`) | копирование дорого, видна разница между перекрытием и раздельными полями |

## Что измеряется

Одинаковый код для всех библиотек (`benchmarks/Benchmark.Strict/Workloads.cs`), по 1000 операций за замер:

| Операция | Что делает |
|---|---|
| создать и разобрать | из значения собрать union и разобрать его; вход берётся по `i % N`, чтобы JIT не свернул константы |
| разобрать готовые | разобрать 1000 заранее собранных union'ов |
| передача по значению | передать 1000 union'ов в метод без инлайна: цена копирования |
| заполнить массив | собрать массив из 1000 union'ов |
| равенство | сравнить два массива поэлементно стандартным равенством типа |

Плюс размер значения в массиве (`Unsafe.SizeOf`) и аллокации (`MemoryDiagnoser`).

Разбор у каждой библиотеки идиоматический (`Match` с лямбдами у OneOf, Dunet, UnionTypes, StructUnion, SumSharp; `Visit` у dotVariant). Для Lite.Union дополнительно есть строка «switch по `Kind`» (без делегатов). В части B на .NET 11 все разбираются одним способом, `switch` по образцу C# 15.

## Методика

- **Самопроверка перед замерами** (`--selfcheck`): каждый адаптер должен вернуть для каждого кейса то же число, что считается из набора напрямую; иначе он не попадает в замер. Равенство проверяется отдельно: тот, чей `==` не сравнивает по значению, помечается и из таблицы равенства исключается. Сочетания, которые CLR не может загрузить, записываются в `benchmarks/Benchmark.Strict/unsupported.csv` с причиной и в замер не идут.
- **Часть A** (`benchmarks/Benchmark.Strict`): .NET 10, BenchmarkDotNet 0.15.8 в **отдельном процессе**, `LaunchCount=2`, `WarmupCount=3`, `IterationCount=10`, время итерации 100 мс, без конкурентного GC. Запуск шардами (набор × число кейсов) с паузой между ними. Прогоны на Windows и в WSL2 (Ubuntu) не смешиваются.
- **Часть B** (`benchmarks/Benchmark.Net11`): .NET 11 RC, там BenchmarkDotNet пока не умеет запускать отдельный процесс, поэтому замеры идут в процессе самого бенчмарка. Эти цифры сравниваются только между собой и только внутри одного прогона, с цифрами части A напрямую не сравниваются.
- В таблицах **медиана** (устойчива к выбросам) в микросекундах на 1000 операций и отношение к `Lite.Union Overlap` (меньше 1 быстрее). Если прогонов несколько, медиана медиан, и указано наибольшее расхождение между прогонами.
- Среда: ноутбук Intel Core i5-9300H (4 ядра, 8 потоков), Windows 11. На время прогона нужно закрыть остальные программы и подключить питание: с запущенными Discord, Firefox и Telegram загрузка ЦП на простое была 27 %, разброс замеров получался до 25 %.

## Как повторить

```bash
cd benchmarks/Benchmark.Strict.Gen && dotnet run           # (пере)генерация адаптеров части A
cd ../Benchmark.Strict
dotnet run -c Release -- --selfcheck                       # проверка адаптеров
./run_strict.sh win-run1                                   # замер, результаты в results/win-run1
dotnet run -c Release -- --report --out report.md --selfcheck results/win-run1/selfcheck.csv \
    --unsupported unsupported.csv results/win-run1         # таблицы

# в WSL одной командой (копирует репозиторий в ~/lite-union-bench, потом удаляет его)
../run_wsl.sh wsl-run1 Benchmark.Strict

# часть B (.NET 11)
cd ../Benchmark.Strict.Gen && dotnet run -- --part b
cd ../Benchmark.Net11 && ./run_net11.sh win-net11
```

## Что уже известно из самопроверки (без замеров времени)

Размеры значения в массиве и работоспособность не зависят от шума, поэтому их можно привести сразу (байт; для трёх кейсов):

| Набор | Lite Overlap | Lite Flat | Lite Boxed | OneOf | StructUnion | SumSharp | SumSharp OneObject | UnionTypes |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| `Values` | 16 | 32 | 8 | 32 | 16 | 16 | 16 | 16 |
| `Refs` | 16 | 32 | 8 | 32 | 16 | 16 | 16 | 32 |
| `Mixed` | 24 | 56 | 8 | 56 | 56 | 56 | 16 | не загружается |
| `Big` | 80 | 200 | 8 | 200 | 136 | 136 | 16 | не загружается |

- Для union'ов из одних чисел размер `Overlap` такой же, как у StructUnion, SumSharp и UnionTypes, и вдвое меньше, чем у OneOf и dotVariant (при 3 кейсах 16 против 32 байт).
- Для смешанных структур перекрытие есть только у Lite.Union: другие библиотеки либо хранят поля раздельно, либо кладут всё в `object` (и боксят).
- `N.SourceGenerators.UnionTypes` на наборах `Mixed` и `Big` генерирует структуру, которую CLR не загружает (`TypeLoadException`: поле-ссылка перекрыто полем-числом), поэтому в этих наборах он отсутствует.
- Размер `Boxed` и `Dunet` показывает только ссылку; сам объект лежит в куче, и его цена видна в колонке аллокаций.

## Оговорки

- Один ноутбук, одна версия каждого пакета, один набор типов на тип нагрузки; на другом железе и с другими типами цифры будут другими.
- Время делегатов у библиотек с `Match` зависит от того, кэширует ли компилятор лямбды; все лямбды без захвата, поэтому кэшируются одинаково.
- Для `Dunet` разбор идёт по иерархии записей на куче, это другая модель (аллокации на каждое создание), а не «такой же union, только медленнее».
- Рукописная структура есть только для `Values` и `Refs`: для остальных наборов «лучшую возможную» написать нельзя без разбора смешанных полей, чем как раз и занимается генератор.
- Встроенный union C# 15 и NonboxingUnion на момент замера требуют .NET 11 RC; поведение финального релиза может отличаться.
